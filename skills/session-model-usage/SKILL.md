# 会话模型用量

此插件的 Windows 程序与查询入口共用统计核心。插件根目录是本文件上方的 `../..`，运行根目录内的 `scripts/session-usage.ps1`。

- 查询当前会话：`& '<插件根目录>/scripts/session-usage.ps1' -Action query`。脚本使用 `CODEX_THREAD_ID`，可通过 `-ThreadId '<会话 UUID>'` 指定其他会话；`-MainOnly` 只统计主会话。
- 启动悬浮条：使用 `-Action launch`。这是独立托盘工具；与官方 Codex 可以按任意顺序启动，普通启动没有调试端口时自动使用 Windows 辅助功能与当前进程的窗口路由日志。Codex 关闭后工具保持待机，官方图标重新打开后自动连接。`ambiguous_host` 表示多个主进程，程序等待唯一实例，不猜测会话。不要强制结束应用或正在运行的任务。
- 查看悬浮条状态：使用 `-Action status`。`running` 表示管理进程运行，待机时 `overlay_visible=false`；`healthy` 表示心跳新鲜。
- 账号额度：整合版 `status.frontend` 提供 `five_hour_remaining`、`weekly_remaining`、`quota_live` 和 `healthy`。余额为剩余百分比，空值表示不可用。前端不健康或 `quota_live=false` 时不能当作实时额度；额度页显示缓存来源与更新时间。额度与本地 token 不能互相换算，不把账号额度称为当前会话 token 用量。
- 同一个托盘提供“账号额度”和“当前会话用量”，任务栏数字条显示账号额度，输入栏旁悬浮条显示当前会话 token。停止操作退出两部分，保持 Codex 运行。活动图表复用会话统计引擎；无请求时间的累计缺口不猜测时间桶，保留部分记录标记。
- 用户可在额度页的“设置”中开关“显示 5 小时余额”，偏好自动保存且默认开启。关闭后任务栏、额度卡片和托盘提示只显示每周或备用余额，5 小时 token 图表仍可查看；该开关不改变 `status.frontend` 返回的真实额度数据。
- 任务栏各自余额下方直接显示小号重置倒计时，如 `3h26m`、`4d12h`，保持原有尺寸。5 小时显示开关同步控制其倒计时；周或备用倒计时使用对应额度的重置时间，缺失显示 `--`，到期显示“待刷新”（英文 `due`），不据此宣称余额已重置。可见且有重置时间时每 15 秒本地刷新，隐藏时停止。
- 活动图表的 5 小时与 24 小时页显示所选时段的周额度消耗；5 小时页有短周期额度时同时显示其消耗，24 小时页及其悬停明细只使用周额度。消耗来自额度历史变化，缺少记录显示 `--`，不能用 token 换算。
- “Codex 状态提示”控制任务栏用量条中间的 Finish（绿）、Ask（橙）、Err（红）与 Working（蓝色呼吸），默认开启且自动保存。跨已确认会话按 P0 Err、P1 Ask、P2 Finish、P4 Working 优先，同级按事件时间排序；不跟随最新或当前会话覆盖其他更高优先级提示。点击余额或托盘仅清除独立闪烁提醒，打开对应会话才逐项确认 Err/Finish；用户回答或任务完成、取消、失败后清除 Ask，不把历史异步调用当作仍待回复的证据。状态只读取已确认的本地会话与当前桌面进程事件，内部生成、命令失败、界面错误和明确自动重试不当作任务故障。
- 数字条和托盘共用右键菜单，与最近会话菜单共用圆角、卡片、悬停、主题、配色、玻璃、字号及面板缩放；保留额度、当前会话用量、恢复连接、刷新和退出入口。操作后或点击外部区域收起，菜单不抢占 Codex 焦点。
- `status.frontend.task_status_enabled` 是显示开关，`task_status` 为上述标签或中性 `Codex`；`working_count`、`ask_count`、`error_count`、`finish_count` 为对应状态数量。结合 `healthy`、`task_source_available` 判断新鲜度与来源，不将记录不可读或中性标签解释为任务成功。
- 点击任务栏中间的 Codex / Working / Ask / Finish / Err 区域向上弹出最近 6 个未归档主会话，按本地侧边栏最近活动顺序排列，排除子智能体和内部审核任务。优先使用 Codex 的显示名称（索引 `name`），旧版索引回退到 `title`；最多显示 12 个字符，超出的第 12 位为省略号。列表和悬停提示均不显示 ID，悬停只显示完整名称，缺失显示“未命名会话”。点击仍使用内部准确 ID；不足 6 个显示实际数量，索引不可用或缓存过期显示等待提示。
- 最近菜单沿用工具的圆角、深浅主题、配色、玻璃偏好与字体/面板缩放。小圆点表示已确认的任务状态，不把状态文字加到会话名称前；打开 Ask 不清除询问，打开 Finish / Err 只确认所选且未更新的状态，点击余额仍打开额度页。
- 最近会话列表只读取最多 128 行的 ID、最多 160 字符标题和最近活动时间，不读取正文；列表不用于识别当前会话或推测任务状态。
- 最近会话展开后，再次点击 Codex 状态区域或点击外部区域收起；输入栏 token 明细同样支持再次点击 token 按钮和外部点击收起。明细内部页签、卡片和滚动继续操作，弹窗不抢占 Codex 焦点，不拦截外部点击。外部检测仅在可见期间运行，不保存点击数据。
- 任务栏悬停详情使用共享圆角主题卡片，沿用深浅主题、配色、玻璃与缩放设置；移开、点击或打开详情时隐藏，避免覆盖已展开的菜单。
- 配色与自定义主辅色同步影响额度、设置、任务栏及输入栏明细的背景和卡片；状态提示保持固定语义色。Working 呼吸遵循 Windows 的动画偏好，隐藏数字条时停止动画。
- 会话明细与磨砂背景使用一致的系统圆角；系统圆角接口不可用时保留透明材质，避免矩形磨砂溢出。玻璃开关与透明度偏好保留。
- 额度概览的描边与系统磨砂圆角按屏幕 DPI 对齐，不随内容缩放扩大；系统圆角接口不可用时改用圆角实色底板，避免四角残留矩形磨砂。
- 诊断异常：使用 `-Action diagnose`，只读本地近期事件；没有自动上传。`recovery_paused` 表示一分钟内五次恢复失败，可点击托盘“恢复连接”或再次 launch。
- `status.compatibility.reason` 提供能力原因：缺少路由日志、同步未完成、输入栏布局不可识别、辅助功能重试、窗口歧义或非本地路由。结合 `codex_version` 判断实际失效环节，不把所有待机状态都解释为版本不匹配。
- 关闭悬浮条：使用 `-Action stop`，这不会关闭 Codex。

查询返回 JSON：`totals` 为总量，`models` 为每个模型及主会话/子智能体分项；各模型的 `reasoning_efforts` 按实际推理强度分组，同组也含 `totals`、`main`、`subagents`。`reasoning_effort: null` 表示未记录，字符串 `none` 表示明确关闭推理。不要用当前模型选择或推理强度填补历史缺失。`threads` 为来源，`warnings` 为证据缺口。`pending` 与空 `totals` 表示还没有用量记录，不能解释为零。`partial` 表示统计不完整，回答时保留这一限制。

同一会话的分页历史按日志中的 `history_base` 边界恢复，派生会话排除父会话基数。无法确认前缀、索引回退或累计明细缺口会保留警告；可核对的累计缺口列为未归属，迟到请求明细会替代缺口。查询结果不能当作服务端账单。

`models[].configurations` 按模型、推理强度和请求服务等级分组，同样含主会话、子智能体与总量。`service_tier` 保留日志等级；`fast_mode: true/false/null` 表示 Fast 请求设置、普通或无法确认，不代表服务端实际等级。迟到的同轮元数据会补齐归属，但不会改变总量；累计缺口和冲突继续标明。

`status.connection_mode` 表示 `windows_accessibility` 或 `cdp`。托盘“恢复连接”只重新尝试连接；不会关闭或重启 Codex。原生路径接受明确的 `/local/` 正式会话或 `client-new-thread` 草稿路由，保留已确认的原生窗口与日志窗口身份，新增同类窗口可通过明确初始路由或剩余唯一配对绑定；证据不足时隐藏。

Micro 本地草稿已确认窗口后先显示等待用量记录的统计条，`thread_id: null` 表示尚无正式会话 ID，不能解释为零用量。临时客户端 ID 不用于查询会话日志；正式路由到来或 Codex 的 `.codex-global-state.json` 提供唯一明确的客户端映射后自动统计，切换时不会沿用旧会话用量。映射读取上限为 2 MiB，只保留 ID 对；冲突、文件未完整写入或不可读取时等待并清除旧结果，不按最近活动猜测。

总 token 已包含输入和输出；缓存输入和推理输出属于分项，不能再次相加。模型归属以本地记录为准，无法确认的用量列在 `unattributed`。查询读已有记录，不调用模型。

悬浮条独立运行，位于输入栏底部权限与背景信息控件之间，首版只识别当前本机的 Codex 会话。调试连接、当前会话识别或控件位置识别失效时，程序隐藏悬浮条并在托盘和 `status` 中说明原因，不根据最近更新的会话猜测。`overlay_visible` 表示实际显示状态。

Codex 失去焦点后悬浮条继续显示，并跟随已确认窗口的层级；最小化、隐藏或切换虚拟桌面时才隐藏。它不是全局置顶窗口，其他应用覆盖 Codex 时也会盖住对应的悬浮条。

选中会话行滚出侧边栏可视区域，或同一会话在“项目”和“最近”中的可见副本变化，不会要求新的路由通知。真正切换到其他会话仍等待明确路由，确认前隐藏旧用量；隐藏控件不用于输入栏定位。
